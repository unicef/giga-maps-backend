# Mapbox

Mapbox is used in two distinct ways, and it is worth keeping them apart.

## 1. Basemap and boundaries — frontend

The frontend renders with **Mapbox GL** and pulls administrative boundaries directly from Mapbox's
own tilesets:

```
mapbox://mapbox.boundaries-adm{level}-v4
```

(seen in the frontend source). `MAPBOX_KEY` is read in the settings overlays. Boundary rendering is
therefore a **frontend↔Mapbox** interaction — the backend is not in the path.

## 2. Boundary metadata — backend

The backend stores its own copy of boundary *metadata* (names, Giga ids, bounding boxes) so it can
associate schools with admin areas. That metadata is loaded from CSVs derived from Mapbox, shipped
in the repository:

```
proco/core/resources/mapbox_boundaries_metadata_admin_0.csv
proco/core/resources/mapbox_boundaries_metadata_admin_1.csv
proco/core/resources/mapbox_boundaries_metadata_admin_2.csv
```

```bash
pipenv run python manage.py load_country_admin_data -af ./proco/core/resources/mapbox_boundaries_metadata_admin_0.csv -at admin0
pipenv run python manage.py load_country_admin_data -af ./proco/core/resources/mapbox_boundaries_metadata_admin_1.csv -at admin1
pipenv run python manage.py load_country_admin_data -af ./proco/core/resources/mapbox_boundaries_metadata_admin_2.csv -at admin2
```

These populate `CountryAdminMetadata`
([proco/locations/models.py:152](../../proco/locations/models.py#L152)), keyed by `giga_id_admin` and
`layer_name` (`admin1` / `admin2`).

School and entity rows then carry nullable `admin1` / `admin2` FKs to those rows, resolved during
master-data publish:

```python
CountryAdminMetadata.objects.filter(
    country=row.country,
    giga_id_admin=row.admin1_id_giga,
    layer_name=CountryAdminMetadata.LAYER_NAME_ADMIN1,
).first()
```

> **These lookups run twice per row inside the publish loop**
> ([proco/data_sources/tasks.py:347](../../proco/data_sources/tasks.py#L347)) and are a known
> performance cost on country-wide publishes. See
> [../08-operations/caching-and-performance.md](../08-operations/caching-and-performance.md).

Backfill for existing schools:

```bash
pipenv run python manage.py populate_admin_id_fields_to_schools -start_school_id=1 -end_school_id=1000000 -at=admin1
pipenv run python manage.py populate_admin_id_fields_to_schools -start_school_id=1 -end_school_id=1000000 -at=admin2
pipenv run python manage.py populate_admin_ui_labels -at=admin1
pipenv run python manage.py populate_admin_ui_labels -at=admin2
```

## 3. Vector tiles — backend, not Mapbox

The school/entity dots are **not** Mapbox-hosted. They are generated by PostGIS in this backend and
served as Mapbox Vector Tiles:

```
GET /api/locations/schools/tiles/connectivity/?z=&x=&y=
Content-Type: application/vnd.mapbox-vector-tile
```

`ST_AsMVT` over an `ST_MakeEnvelope` bounding box —
[../03-user-flows/map-exploration.md](../03-user-flows/map-exploration.md) has the full mechanism,
including the `LIMIT` truncation behaviour and the unparameterised-SQL issue.

## Other Mapbox-adjacent pieces

`django-mapbox-location-field` 2.0.0 provides a map point widget for admin forms.

## Troubleshooting

| Symptom | Where the problem is |
|---|---|
| Basemap missing, dots present | Frontend / `MAPBOX_KEY` |
| Basemap fine, dots missing | Backend tiles — check the read replica |
| Admin boundaries missing on the map | Frontend Mapbox boundary tilesets |
| Schools not grouped by admin area | `CountryAdminMetadata` not loaded, or `admin1`/`admin2` FKs null |
| Admin names blank in the UI | `populate_admin_ui_labels` not run |
